The problem

Most comments are fine. The rare ones do the damage.

The Jigsaw dataset holds Wikipedia talk-page comments rated by human reviewers. A useful classifier has to find threats that make up 0.3% of the data without burying moderators in false alarms. It also has to give a probability for each label, because a comment can be several kinds of toxic at the same time.

Data: Jigsaw Toxic Comment Classification Challenge (Kaggle).

Rebuild

What changed from the first version

The 2022 version scored well on paper, but it was tested on balanced samples that don't look like real traffic. The rebuild fixes that.

v1 2022

  • Six separate yes/no models, each trained on a down-sampled slice of the data
  • Tested on 50/50 balanced splits, which inflates precision and F1
  • Word counts only, so misspellings like f*ck slip through
  • Fixed 0.5 cut-off for every label
  • Saving step stored the wrong model

v2 2026

  • One multilabel model trained on all 159,571 comments
  • Scored on Kaggle's official test set, with its real class mix
  • Word and character n-grams catch obfuscated spellings
  • A separate threshold for each label, tuned on a validation split
  • One saved pipeline that takes raw text and returns six probabilities
  • Explainability, error analysis and an identity-term fairness audit

The gap is measurable. Section 9b scores the identical v2 predictions both ways: mean F1 is 0.820 on balanced per-label samples but 0.561 on the real class distribution. severe_toxic is the extreme case, at 0.887 balanced against 0.291 real, a threefold overstatement. Nothing about the model changes between those two numbers, only the test set, which is why every figure on this page uses the real distribution.

Pipeline

From raw comment to six scores

  1. Light cleaning

    Lowercase, and swap URLs, IP addresses and user tags for tokens. Symbols stay in, because they help spot disguised words.

  2. Stratified split

    Multilabel iterative stratification keeps rare labels like threat present in both train and validation.

  3. Word + char TF-IDF

    1–2 word n-grams plus 2–5 character n-grams, around 200K sparse features in total.

  4. Model comparison

    Naive Bayes, Logistic Regression and Linear SVM, compared on validation ROC-AUC and PR-AUC.

  5. Threshold tuning

    For each label, the cut-off that maximises F1 on validation instead of a flat 0.5.

  6. Test and package

    One pass on the official test set, then saved as a single joblib pipeline.

Explainability

Why did it flag that?

Logistic regression weights show which n-grams push each label up. Error analysis looks at the highest-scoring clean comments and the lowest-scoring toxic ones. The usual misses are comments that quote abuse to report it, and toxic comments with no profanity, such as sarcasm or veiled threats.

Fairness audit

Mentioning a group is not hate

Classifiers trained on this data flag harmless comments just because they name an identity group, and this one does too. Across all non-toxic test comments the false-positive rate is 8.09%. Below is that rate for non-toxic comments containing each term, as a multiple of the baseline. Terms with fewer than 20 such comments are left out.

gay is the worst case at 5.8× the baseline, meaning nearly half of non-toxic comments containing the word are flagged. This is a property of the training data, not a bug in the model, and it is the strongest argument against shipping this as an automated filter. Fixes worth trying: augmenting with neutral identity mentions, reviewing thresholds per group, or retraining on Jigsaw's Unintended Bias in Toxicity dataset.
